改用 MongoDB 的做法（AI 提出，使用者回覆「MongoDB 照上面做」）：
- 交付物 `schema.sql` 改為 `schema.mongo.js`：每個集合的 JSON Schema 驗證與索引（偏離 docs/01 ⑤ 的檔名）。
- 一個名詞一個集合；只屬於它、不會被別處指到的子項目嵌在文件裡（例：工作許可的每次核准、個資請求的延長紀錄）。
- 單一文件的限制用集合的驗證規則與唯一索引（例：同一雇主在職員工編號不重複用部分索引）。
- 跨集合的一致性一律放 service 層，配合多文件交易（需以 replica set 部署）；MongoDB 不檢查引用是否存在，也由 service 層檢查。
- P2 的 A「只新增」為新增一份文件；變更紀錄放獨立的集合。
- API 維持 REST＋OpenAPI 3.1。
